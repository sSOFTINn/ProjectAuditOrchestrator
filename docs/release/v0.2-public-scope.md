# v0.2 product scope

Baseline release: `v0.2.0`. Later v0.2 maintenance candidates are listed in the
[changelog](../../CHANGELOG.md); an unreleased entry does not establish a
published tag. Verify the selected release's signature and bound checksums
before use.
Local builds retain their exact version/revision in private `BUILD-METADATA.json`;
an older RC is not the identity of a later release.

This document defines the intended distribution, supported interfaces and
operational boundaries. Planning, review reports and acceptance records remain
internal. Local preparation and passing tests do not approve publication.

## Distribution and build identity

The agreed distribution is reviewed source plus Windows AMD64 ZIP and Linux
AMD64 tar.gz. Each archive contains the host PAO executable and the same owned
static Linux AMD64 `pao-sandbox-linux-amd64` supervisor, ten adapter manifests,
three blank `UNAPPROVED`/unfilled JSON templates, beginner instructions,
LICENSE/NOTICE, exact Go license, a version/platform record and content manifest. Archive
allowlists reject missing/extra payloads. Scanners, runtime images, databases,
rule packs, private configuration, reports and raw evidence are excluded.

The canonical module is `github.com/sSOFTINn/ProjectAuditOrchestrator`.
The exact selected toolchain is Go 1.27.1. Both owned binaries include Go runtime
and stdlib. Cached third-party schemas and Python wheels under `schemas/vendor`
are source-only development resources, with original licenses, attribution and
hashes; they are not binary payload or product Python runtime dependencies.
Source archive/history requires its own disclosure review.

The public downloadable payload contains exactly both archives and
`SHA256SUMS.txt`. Reviewed source is published in the existing repository at the
signed tag for the selected release version, with GitHub's source downloads. The signed tag annotation
must bind the approved commit and the SHA-256 of `SHA256SUMS.txt` so the signature
also binds the binary payload. The trusted signer and exact values need separate
owner approval before signing/publication.

Test reports, `BUILD-METADATA.json`, the CycloneDX SBOM and unsigned in-toto
provenance are internal evidence. The builder writes them to a separate
`evidence` directory. They must not be uploaded as public Actions artifacts,
release assets or committed source. Each archive exposes only `VERSION.json`
(version, platform, architecture) plus its content manifest; the CLI `doctor`
retains the product identity needed for support. `version`, `doctor`, filenames
and metadata share one exact version. Internal build metadata records commit,
clean/modified state, source content digest, supervisor/binary/archive hashes, Go version and
an explicit timestamp from the approved source commit.
Dirty sources are permitted only in explicitly requested prerelease builds,
which cannot impersonate a clean commit or stable release.

Reproducibility requires byte-identical public archives and checksum manifest
from two fresh builds with the same source bytes, toolchain, version and
timestamp. Local repeatability is not independent reproduction. Hosted and
independent candidate builds must also match the approved public bytes.
Internal hosted metadata may differ in invocation identity. No public keyless
attestation is emitted; internal unsigned provenance is not a signature.

This is a regular public GitHub release, not a GitHub prerelease. PAO remains
pre-1.0 and compatibility changes must be called out in release notes. A stable
build requires a clean selected commit on `main`; release preparation on a
modified worktree is not that candidate. Uncommitted files must be classified
by provenance before selection. Unresolved provenance blocks release; preserve
excluded operational material privately rather than discarding it.

## Current behavior and support

The configured CLI is `pao audit --config FILE --profile NAME [--execute]`
with mandatory preview and exact run-specific confirmation. Configuration v2,
catalog v1, provider v1alpha1, adapter v1alpha2, plan v1alpha1, unified-report v1
and producer v1 are versioned contracts, validated with a bounded
positive/negative corpus. `internal/*` is not a supported external Go API.
Internal policy/correlation/baseline and JSONL/SARIF 2.1.0/CycloneDX 1.5/SPDX 2.3
renderers are library helpers, not additional configured CLI output modes.

| Boundary | Product contract |
| --- | --- |
| Hosts/archives | Windows 11 x64 and Ubuntu 24.04 LTS x64; no ARM/macOS release claim |
| Scanner engine | Local Docker Desktop Linux VM, explicit supported local endpoint, exact approved Docker CLI/image, non-root VM identity |
| Unsupported engines | Ordinary/rootless Docker Engine, remote contexts and root scanners |
| Profiles | `fast`, `deep-sca`, `license`, `secrets`, `sast`, `ci-security`, `sbom-quality`, explicit `mvp` |
| OSV ecosystem support | Current local DB covers Go only; present PyPI/npm/crates.io inputs are `DB_ECOSYSTEM_UNSUPPORTED` |
| Python/custom formats | `requirements.lock` and `build-requirements.lock` remain `UNSUPPORTED_INPUT_FORMAT`; detection is a filename hint |
| Inventory adequacy | Detected expected ecosystems compared with verified Syft inventory; Actions-only inventory does not cover PyPI |
| SBOM quality | Owner-approved sbomqs on captured SBOM only; informational score, no security/legal or inventory-completeness verdict |
| VCS metadata | Target Git subprocess is disabled; snapshot VCS remains `UNAVAILABLE/UNKNOWN`; no full history secret-scan claim |
| Updates/telemetry | Manual update/rollback, no telemetry or automatic cleanup of private evidence |
| Network | Scanner execution denies network; tool/database preparation is a separate explicit operator action with source/version/hash and source-specific versioned freshness policy |

Only the exact Docker Desktop versions that pass native acceptance are supported.
Hosted Windows Server CI is additional evidence, not Windows 11 acceptance.
Required Windows and Linux hosted checks must block merge to `main`; settings
availability and protection readback are separate gates. Missing or stale
prerequisites retain partial/review states. Future network and agent modes are
post-v0.2 design work only; no implementation or implicit remote transmission
is included in this release.

Applicability, support, execution and parsing have separate reasons. A truly
absent input is `SKIPPED_NOT_APPLICABLE`; a present unsupported ecosystem is not.
`coverage_complete` retains execution/parsing meaning. `inventory_coverage`
and `analysis_coverage_complete` add detected ecosystem/format gaps. Adequacy
does not prove every package, runtime, build extra or transitive dependency.
The local PAO/Go release SBOM is not an independent full transitive inventory.

Original `run_producer` and current `report_producer` each record PAO
version/revision/source content/executable SHA-256/Go identity. An old run
without that evidence stays `UNKNOWN_HISTORICAL`; rerendering cannot invent
its origin. Configured CLI codes are `0` preview/help, `3` CLI/config/I/O error,
`4` review/incomplete execution/report, and `5` refused confirmation/stale
preview/policy-blocked launch. No current scanner execution yields automatic PASS.
The non-configured inspection commands and internal legacy exit helper have
separate contracts; see the operator guide for the configured workflow.

## Isolation and verification requirements

Target snapshot/capture enforce 64 MiB per file, 4 GiB per pass and 100,000 tree
entries during I/O, with cancellation and identity/drift refusal. The scanner
reads only a verified private target capture. Tool/state/DB/rules/captured-input
bytes are frozen into bounded per-execution copies. Native Docker CLI and the
supervisor are pinned/frozen before use. Trusted same-account/privileged actors
and adjacent native DLL/plugin compatibility are explicit residual boundaries
in [frozen-inputs.md](../security/frozen-inputs.md).

Output and scratch no longer use a writable host output mount. The owned
supervisor transfers bounded results from VM tmpfs: `/tmp` is 64 MiB and
4,096 inodes; `/pao/out` is at most 128 MiB (lower for a smaller adapter budget)
and 4,096 inodes. Result bytes are at most the admitted adapter limit, capped
at 64 MiB, with a separate 256 KiB diagnostic prefix. CPU/RAM/time limits are
separate from these filesystem quotas.

Release acceptance requires the exact clean candidate and its archives on both
target operating systems, including Docker CLI/supervisor compatibility and
scanner-version contracts. Synthetic tests alone do not establish that support.

Native scanner JSON is parsed inside PAO. The common native parser has a 64 MiB
input cap, depth 64, 1,000,000 JSON values and 10,000 projected observations.
SBOMQS uses a separate legacy parser with a 64 MiB cap and result validation;
it does not share the common depth/value walker. Separate parser-process
isolation is absent, so a parser failure can affect PAO. Schema checks for
synthetic producer/export documents do not validate every future scanner field
or establish complete compliance with upstream specifications.

Local workflow contracts keep build/tests read-only and upload only the three
allowlisted public files after verification and a second byte-identical build.
Internal evidence stays on the runner. Hosted execution for the exact selected
candidate remains a release requirement. No workflow publishes a release,
creates an attestation, signs a tag or changes visibility.

Current-doc redaction does not sanitize Git history. Before publication, close
runtime/onboarding acceptance, findings and human review, source/history privacy
review, immutable candidate CI, exact archive verification, reachable private
vulnerability reporting, approved protections/settings and trusted signed-tag
verification bound to public hashes. Visibility/source disclosure, tag/run/settings and release asset
publication have distinct exact approvals. No commit, tag, release or visibility
change is authorized by successful local preparation alone.
