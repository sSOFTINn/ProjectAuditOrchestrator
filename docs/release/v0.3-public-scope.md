# PAO v0.3 public scope

The v0.3 candidate adds an archive-to-audit CLI workflow to the
[bounded v0.2 audit scope](v0.2-public-scope.md). A local source tree or successful
unit test does not establish publication or native platform acceptance.

Supported target hosts remain Windows 11 AMD64 and Ubuntu 24.04 AMD64, using
the local Linux VM of Docker Desktop. The exact tested Desktop versions and
archive identities must be recorded in the final release notes. Ordinary or
rootless Engine, remote endpoints, ARM, macOS and a GUI are outside this scope.

The native candidate checks use these environments:

| Host | Docker Desktop | Docker CLI |
| --- | --- | --- |
| Windows 11 AMD64 | 4.97.0 | 29.9.2 |
| Ubuntu 24.04.5 AMD64 | 4.93.0 | 29.8.2 |

These are measured environment versions, not an acceptance claim for arbitrary
other versions or a substitute for the final archive-specific results.

## Commands and formats

| Interface | Contract |
| --- | --- |
| `setup --root PATH --profile secrets\|mvp` | Read-only preparation plan; no network |
| `setup ... --apply` | Target-directory separation check, exact plan confirmation, public downloads, synthetic verification and separate final owner approval |
| `setup --verify --config FILE` | Explicit fixed synthetic verification, new evidence, separate approval and new configuration |
| `doctor --config FILE --profile mvp --json` | Read-only aggregate prerequisite diagnostics, not an audit verdict |
| `recover --config FILE --run ID` | Read-only inspection of one pending lifecycle record |
| `recover ... --apply` | Exact `RECOVER ID`, ownership-verified container cleanup, evidence preserved |
| `audit --config FILE --profile NAME --execute` | Offline scanner execution after the exact current `RUN ID DIGEST` |

Configuration v3 adds the private shared `installation_state`. Legacy v1/v2
can be previewed and imported without rewriting the originals; execution
requires migration. The private `pao.dev/run-summary/v1` records execution,
coverage, review, numeric exit status and result locations independently.
The existing numeric audit codes remain unchanged.

Setup pins tools, runtime base and preparation dependencies in packaged recipes.
Changing vulnerability databases retain source metadata, actual snapshot age,
provider checksums and local SHA-256. Setup has no target-content input or target
package-manager lifecycle. Audit never downloads updates. Blank templates are
intentionally unapproved; the owner's review follows preparation and measured
synthetic verification of the actual installation.

The same root/profile/recipe resumes a verified generation. Refreshing stale
databases or a changed Docker CLI/runtime requires a new installation root;
there is no in-place `--refresh`. Keep previous evidence and configurations
when preparing a replacement installation.

## Distribution and acceptance

The distribution is source, Windows ZIP, Linux tar.gz, `SHA256SUMS.txt` and a
signed tag that binds source and checksum manifest. Each binary archive has
29 allowlisted files, including the owned sandbox/probe and seven recipe files.
Third-party scanners, wheels, images, databases and private results stay outside
the archives. PAO-authored sample Opengrep rules are included with attribution.

Release acceptance requires native archive-based setup, all ten adapters and
the Syft-to-sbomqs chain on both hosts, repeated offline execution, interrupted
setup/run recovery, resource/permission/tamper checks, migration and rollback,
source/license/privacy/security review and reproducible builds. Required skipped
tests remain open gates. Probe success alone does not establish scanner compatibility.

Protected evidence and backup readiness remain operator obligations under the
audit-storage policy. Any explicit exception for this release is recorded
privately without presenting an unperformed restore check as verified.
Final publication requires the owner's exact commit/tag/archive approval.
No local report or generated date substitutes for that decision. Internal
operational evidence is not shipped.
